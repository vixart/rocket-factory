# Технические заметки

Документация по неочевидным местам проекта: почему сделано именно так и что сломается,
если сделать иначе. Всё, что нужно знать, чтобы менять код, не наступая на грабли,
на которые уже наступили.

Здесь **нет** описания того, что и так видно из кода (структура пакетов, сигнатуры,
список эндпоинтов). Только решения, у которых есть цена и альтернатива.

| Документ | О чём |
|---|---|
| [architecture.md](architecture.md) | Слои, три модели данных, инверсия зависимостей, DI и порядок закрытия ресурсов |
| [auth.md](auth.md) | Как session-uuid проходит через HTTP → gRPC → Kafka и почему без этого падает `Unauthenticated` |
| [data.md](data.md) | Транзакции через контекст, `SELECT ... FOR UPDATE` и порядок блокировок, JSONB, пул соединений |
| [kafka.md](kafka.md) | Семантика доставки, идемпотентность, требования sarama, создание топиков |
| [observability.md](observability.md) | Логи, метрики, трейсы: устройство пайплайна и конвенция уровней логирования |
| [infrastructure.md](infrastructure.md) | Taskfile, Docker, compose: сборка, порядок подъёма, ускорения и ловушки терминала |
| [testing.md](testing.md) | Виды тестов, что чем покрыто, фикстуры нагрузочного теста |

## Как читать

Каждый раздел ссылается на конкретные файлы. Ссылки вида `путь/файл.go:42` — это место
в коде, где решение реализовано.

Проект в основном прокомментирован по-русски. Документация написана так, чтобы пережить
перевод кода и комментариев на английский: знание о причинах решений остаётся здесь.
